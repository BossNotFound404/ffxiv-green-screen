# 导出带透明通道的特效

本页记录 v0.8.1 从棚内画面估算透明度和提取发光的试验。原生导出另行研究技能与背景合成时的绘制数据。

## 拍角色施放的技能

在普通视角进棚，摆好机位，把要用的技能放在快捷键上。点 **拍角色技能**，插件切黑棚并暂时隐藏本人模型和游戏界面。等绿幕面板提示 **棚色已稳定，请在游戏里施放技能**，按一次技能快捷键。让场内其他特效先消失，避免它们抢先触发拍摄。

看到技能后，插件从随后 360 毫秒内实际读到的画面中选出发光最强的一张，再恢复棚色和界面。点 **打开结果文件夹**，其中 **black.png** 是选中的游戏原帧，**glow-add.png** 是同一帧的发光层，按直通 Alpha 导入，在线性光下以「添加」混合使用。单次黑棚曝光能记录可见的光，烟雾遮暗背景的程度仍无法从这张图确定。

这个按钮只拍一帧，用于观察黑棚中的技能形状和亮度。

## 拍 VFXEditor 地面预览

1. 在普通视角进棚，启用 **VFXEditor 1.9.4.6** 和 **Brio 0.8.0.12**。在 VFXEditor 用 **Spawn → On Ground** 放一个地面预览，保持镜头不动，让画面边缘留出纯色。面板和游戏界面可以开着。如果取景里还有其他角色、宠物或模型，请先移出画面。
2. 在想要的特效状态出现时，点绿幕面板的 **拍地面预览**。插件尝试暂停这一件地面预览，临时隐藏本人模型和游戏界面，先拍黑棚、白棚、绿棚，再各复拍一次黑棚和白棚，共五张图。每张都在天空、地面和两侧边缘连续两次读到目标颜色后拍摄。可以点「取消导出」或输入 `/rtstudio 取消导出`。
3. 拍完自动恢复棚色、角色可见度、游戏界面及该预览原来的播放速度。点 **打开结果文件夹**。通过时取 **effect.png**，它是直通 Alpha 的单张 PNG。**green.png** 为实拍绿底，**green-recomposed.png** 为拿导出的 PNG 重新叠回绿底的效果，两张可以直接来回对照。

对照按像素计算。插件用黑白两张还原透明图，以独立的绿棚照片检验颜色与边缘，再分别比较两张黑棚和两张白棚照片，检查这段时间里仍在变化的粒子。容差为每通道 8/255。前景为空、全屏没有共同底色，或有前景像素超差时，结果进入 **review-** 文件夹，其中有 **candidate.png**、五张实拍图及 **report.json**，可定位是换底受光、发光混合还是首尾画面变化。稳定超时或读取失败可按面板提示重新试拍。结果位于插件配置目录中的 **Exports**。

v0.8.1 试用 Brio 对象面板的「暂停」。拍完或取消时，原先播放中的这一件预览可能从头播放。原本就已暂停的预览维持暂停。首次黑棚和首次白棚还各存一张同棚对照图（约早 0.6 秒），用来判断换色之前画面是否已在变化。下方的离线工具也可合成已对齐的黑白图像序列。

对于接近加法发光的素材，待复核目录还可能提供 **glow-add.png**。它只取自第一次黑棚曝光，使用时按直通 Alpha 导入并选择「添加」混合。普通透明图、实拍绿棚对照和首尾画面的一致性分别记录在报告里。

## 离线工具所需素材

1. 固定镜头、分辨率、灯光、曝光和后期设置。关闭聊天、插件窗口、本人名牌等界面。若目标是纯特效，确认角色和其他模型已移出画面或隐藏干净。留在两张图里的静止界面和人物都会被视作前景。
2. 等棚色切换结束，再截取相同区域。空场采样应分别接近 RGB **0, 0, 0** 和 **255, 255, 255**。地板仍有渐变、上下半屏有色差或画面处于蓝白网点过渡时，请等背景稳定。
3. 使用全范围、标准 sRGB 的 **8 位 RGB 或不透明 RGBA PNG**。HDR、视频限幅、额外调色和压缩色边需要在导出 PNG 前处理。两次播放需对齐到特效的同一状态。逐帧对照外弧、电纹和粒子的位置，独立重播中的随机粒子可能无法配对。

## 运行

在源码根目录打开终端，将输入图片放在新建的 `shots` 子目录。以下命令使用 Windows 自带的 Windows PowerShell 5.1。输出目录的上级需要存在，工具会新建最后一级目录。

单帧会生成 `.\shots\rgba\effect.png`。

```powershell
powershell.exe -NoProfile -File .\tools\export-alpha.ps1 -Black ".\shots\black.png" -White ".\shots\white.png" -Output ".\shots\rgba"
```

录制整段时，将两次录制按相同帧率导出到两个目录。两边都从同一特效帧开始编号，例如各自都有 `0001.png`、`0002.png`。工具逐个配对同名帧，输出沿用帧名。

```powershell
powershell.exe -NoProfile -File .\tools\export-alpha.ps1 -Black ".\shots\black" -White ".\shots\white" -Output ".\shots\rgba-frames"
```

在剪辑软件按录制帧率导入 PNG 序列，Alpha 解释选择 **Straight / 直接**。默认按线性光混合计算，RGB 以 sRGB 编码存储。如果已知输入在编码值上混合，可加参数 `-BlendSpace Encoded` 并导出到另一个新目录。比较两种结果时，用同一机位拍下的第三种底色做对照，合成软件也应使用对应的混合空间。

## 怎么判断能否用

- **普通半透明**。把导出的 PNG 放在与原绿棚同色的底上，与实拍绿棚对比。看贴地扇面的填色、外弧和细电纹能否同时重现。PNG 中完全透明像素的 RGB 写为零，抗锯齿边缘保留相应覆盖率。
- **错帧或染色**。工具会把导出结果重新叠回黑、白底，报告任一通道与输入相差超过 8 个色阶的像素数。重影、轮廓双线或大面积超差时，应核对帧对齐与角色受光。灰色物体错位、白底高光截断等情况可能得到很低甚至零误差；第三底色对照仍然必要。
- **加法发光和折射**。在不同颜色上仍要发亮的光晕，可能需要从黑底画面保留独立发光层，并在合成时使用「添加」。对于同时有实体和光晕的特效，把完整黑底叠加到已含发光的 RGBA 会重复提亮，需要单独分离发光贡献。热浪或折射会改变其后画面的取样位置，也需要在目标背景上另行处理。

## 透明合成的依据

普通透明叠加满足 `画面 = 前景 × Alpha + 背景 × (1 − Alpha)`。在稳定的纯黑和纯白背景上，两张图的各通道差值给出透射率。工具用三通道平均值估算 Alpha，用黑白两次观测估算前景，再保存直接 Alpha。该推导依赖两张图中的前景及其光照一致。[W3C 合成公式](https://www.w3.org/TR/compositing-1/#simplealphacompositing) · [PNG 透明度表示](https://www.w3.org/TR/png-3/#6AlphaRepresentation)

对于依赖场景时间的粒子或受后期影响的颜色，速度读回为零仍可能出现变化。验证时请保留黑白复拍图和实拍绿棚。v0.8.1 已支持从单张黑棚实拍输出用于「添加」的发光图。要在混合型特效中提取独立的发光或折射贡献，还需读取同一次游戏绘制的数据。

仓库的 `tools/checks/Test-AlphaExport.ps1` 用已知颜色和透明度生成黑白两组输入，并把导出结果合成到独立绿底做比较。它也覆盖不同尺寸、帧名缺失、已有输出及不符合普通透明模型的样本。实机特效的重播同步、受光一致性及发光还原需要用录制素材验收。
